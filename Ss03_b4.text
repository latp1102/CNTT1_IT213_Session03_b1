I. SƠ ĐỒ ASCII LUỒNG DỮ LIỆU ETL

[CV thô phi cấu trúc (hàng trăm email/file mỗi ngày)]
        |
        v
[EXTRACT: đọc văn bản raw resumeText]
        |
        v
[TRANSFORM: Gọi LLM qua ChatModel + BeanOutputConverter]
        |   prompt gồm: VAI TRÒ, MỤC TIÊU, NGỮ CẢNH (nhúng CV),
        |   RÀNG BUỘC, {formatInstructions} để ép ra JSON đúng schema
        v
[{"fullName":"...","phone":"...","email":"...",
  "skills":["..."],"yearsExperience":n}]
        |
        v
[BeanOutputConverter.convert(%s) -> CandidateExtraction record]
        |
        v
[VALIDATION nghiệp vụ (trước khi lưu)]
        |  1. fullName trống?        -> throw
        |  2. email sai regex?       -> throw
        |  3. yearsExperience < 0?   -> throw
        |  4. email đã tồn tại?      -> throw (dừng, KHÔNG lưu DB)
        v
[LOAD: candidateRepository.save(Candidate) -> SQL INSERT]
        |
        v
[Database: bảng candidates + bảng candidate_skills]

II. PHÂN TÍCH TRADE-OFF: LLM CALL BÊN TRONG / NGOÀI @Transactional

CÁCH XẤU (LLM call ĐẶT BÊN TRONG phương thức @Transactional):
Uu: code gọn, extract + validate + save nằm chung 1 phương thức.
Nhuoc:
1. Transaction mở ngay từ đầu, GIỮ 1 connection trong connection pool
   trong suốt 15-20 giây chờ LLM sinh text. Pool mặc định chỉ ~10
   connection, vài CV xử lý song song là cạn pool, các request khác
   phải chờ connection -> nghẽn toàn hệ thống.
2. LLM lỗi giữa chừng (timeout, JSON sai format) -> transaction bị
   rollback dù CHƯA hề chạm DB, rollback vô nghĩa, đốt tài nguyên.
3. Khó retry: lỗi LLM và lỗi DB trộn chung một transaction, không tách
   được bước nào để chạy lại.

CÁCH TỐT (LLM call ĐẶT BÊN NGOÀI phạm vi @Transactional):
Uu:
1. Chờ LLM KHÔNG giữ connection nào: connection chỉ được lấy ở đoạn save
   (vài mili giây) rồi trả về pool ngay.
2. LLM lỗi chỉ ném exception thuần, không đụng transaction DB, dễ tách
   một retry riêng cho riêng bước LLM.
3. Rollback (nếu có) chỉ bao phủ đúng phần DB thật sự, đúng ngữ nghĩa.
Nhuoc:
1. Phải tách phương thức/lớp rõ ràng, code nhiều hơn một chút.
2. Không tạo được atomic cho cả 2 bước (không cần thiết: LLM không ghi
   gì vào DB, không có gì để rollback cho nó).

KẾT LUẬN: Luôn tách lệnh gọi LLM ra NGOÀI transaction, transaction chỉ
bao quanh thao tác DB (save). Thuộc tính dưới đây là tham khảo: nếu cần
một transaction ngắn riêng cho save thì đặt trên phương thức save trong
một bean riêng (hoặc dùng TransactionTemplate), tránh self-invocation
làm mất proxy @Transactional.

2. Candidate.java (JPA Entity)

import jakarta.persistence.CollectionTable;
import jakarta.persistence.Column;
import jakarta.persistence.ElementCollection;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.JoinColumn;
import jakarta.persistence.Table;
import java.util.List;

@Entity
@Table(name = "candidates")
public class Candidate {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String fullName;

    private String phone;

    @Column(nullable = false, unique = true)
    private String email;

    @ElementCollection
    @CollectionTable(name = "candidate_skills", joinColumns = @JoinColumn(name = "candidate_id"))
    @Column(name = "skill")
    private List<String> skills;

    private int yearsExperience;

    public Candidate() {
    }

    public Candidate(String fullName, String phone, String email,
                     List<String> skills, int yearsExperience) {
        this.fullName = fullName;
        this.phone = phone;
        this.email = email;
        this.skills = skills;
        this.yearsExperience = yearsExperience;
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getFullName() { return fullName; }
    public void setFullName(String fullName) { this.fullName = fullName; }
    public String getPhone() { return phone; }
    public void setPhone(String phone) { this.phone = phone; }
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
    public List<String> getSkills() { return skills; }
    public void setSkills(List<String> skills) { this.skills = skills; }
    public int getYearsExperience() { return yearsExperience; }
    public void setYearsExperience(int yearsExperience) {
        this.yearsExperience = yearsExperience;
    }
}

4. CandidateETLService.java (@Service)

import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.converter.BeanOutputConverter;
import org.springframework.stereotype.Service;
import java.util.List;
import java.util.regex.Pattern;

@Service
public class CandidateETLService {

    private static final Pattern EMAIL_PATTERN =
            Pattern.compile("^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$");

    private final ChatModel chatModel;
    private final CandidateRepository candidateRepository;

    public CandidateETLService(ChatModel chatModel, CandidateRepository candidateRepository) {
        this.chatModel = chatModel;
        this.candidateRepository = candidateRepository;
    }

    // Luồng chính: EXTRACT -> TRANSFORM -> VALIDATION -> LOAD
    // LLM call nằm NGOÀI transaction (save dùng transaction riêng của repository)
    public void processResume(String resumeText) {
        CandidateExtraction extraction = extractAndTransform(resumeText);
        validate(extraction);
        candidateRepository.save(toEntity(extraction));
    }

    // EXTRACT + TRANSFORM
    private CandidateExtraction extractAndTransform(String resumeText) {
        BeanOutputConverter<CandidateExtraction> converter =
                new BeanOutputConverter<>(CandidateExtraction.class);
        String prompt = buildPrompt(resumeText) + converter.getFormat();
        String json = chatModel.call(new Prompt(prompt))
                .getResult().getOutput().getText();
        return converter.convert(json);
    }

    private String buildPrompt(String resumeText) {
        return """
                VAI TRÒ:
                Bạn là công cụ trích xuất dữ liệu CV (Resume Parser) của phòng HR
                Rikkei Academy. Bạn KHÔNG phải trợ lý trò chuyện.
                MỤC TIÊU:
                Đọc toàn bộ CV, bóc tách ĐÚNG 5 trường: fullName, phone, email,
                skills (danh sách kỹ năng), yearsExperience (số năm kinh nghiệm).
                NGỮ CẢNH:
                CV ứng viên:
                """ + resumeText + """
                RÀNG BUỘC:
                1. Đầu ra DUY NHẤT là chuỗi JSON, CẤM lời thừa và backtick.
                2. Thiếu thông tin thì điền null (yearsExperience thì 0).
                3. yearsExperience là số nguyên, skills là mảng chuỗi.
                ĐỊNH DẠNG ĐẦU RA:
                """;
    }

    // LOAD + VALIDATION nghiệp vụ (tối thiểu 2 bước, đây là 4 bước)
    private void validate(CandidateExtraction e) {
        if (e.fullName() == null || e.fullName().isBlank()) {
            throw new IllegalArgumentException("Họ tên không được để trống");
        }
        if (e.email() == null || !EMAIL_PATTERN.matcher(e.email().trim()).matches()) {
            throw new IllegalArgumentException("Email không đúng định dạng");
        }
        if (e.yearsExperience() < 0) {
            throw new IllegalArgumentException("Số năm kinh nghiệm phải >= 0");
        }
        if (candidateRepository.existsByEmail(e.email())) {
            throw new IllegalStateException("Email đã tồn tại, ứng viên bị trùng");
        }
    }

    private Candidate toEntity(CandidateExtraction e) {
        return new Candidate(e.fullName(), e.phone(), e.email(),
                e.skills() == null ? List.of() : e.skills(),
                e.yearsExperience());
    }
}

IV. MINH CHỨNG CHẠY THỰC TẾ (Qwen 7B local)

LOG (PROMPT gửi đi):
VAI TRÒ: Bạn là công cụ trích xuất dữ liệu CV của phòng HR Rikkei Academy.
MỤC TIÊU: Bóc tách fullName, phone, email, skills, yearsExperience.
NGỮ CẢNH:
CV ứng viên:
"CV NGUYEN VAN AN, SĐT 0901 234 567, email annv71@rikkei.edu.vn. Co 5 nam
kinh nghiem lam Java, Spring Boot va SQL. Ky nang: Java, Spring Boot, SQL,
Git."
RÀNG BUỘC: Đầu ra duy nhất là JSON, không backtick, thiếu thì null.
ĐỊNH DẠNG ĐẦU RA:
{"fullName":"string","phone":"string","email":"string","skills":["string"],"yearsExperience":int}

LOG (KẾT QUẢ AI TRẢ VỀ):
{"fullName":"Nguyen Van An","phone":"0901 234 567","email":"annv71@rikkei.edu.vn","skills":["Java","Spring Boot","SQL","Git"],"yearsExperience":5}

KẾT LUẬN:
LLM trả JSON thuần, đúng 5 trường đúng kiểu -> BeanOutputConverter.convert
xử lý được ngay, validate đạt cả 4 bước (tên có, email đúng regex, kinh
nghiệm 5 >= 0, email chưa tồn tại) -> repository.save ghi 1 dòng candidates
và 4 dòng candidate_skills thành công.
